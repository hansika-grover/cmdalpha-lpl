# Sentinel

**Early detection of elder financial exploitation, built for LPL's workflow, with a person making every decision.**
Team cmd+alpha · LPL WealthX Hackathon, Infinium '26 (IIIT Hyderabad)

Older Americans reported **$7.75 billion** in fraud losses to the FBI in 2025, up 59% in a year: one complaint every
2.6 minutes ([IC3 2025](https://www.ic3.gov/annualreport/reports/2025_ic3report.pdf)). Firms already have the legal tools
to act (FINRA Rule 2165 holds, Rule 4512 trusted contacts, Senior Safe Act immunity), but deciding *when* still depends on
one person noticing one odd event. Fixed withdrawal thresholds miss small, repeated thefts and flag legitimate large
withdrawals, and the richest evidence, what the client told their advisor, is never read systematically.

Sentinel joins three streams LPL already holds (money movement, account changes and advisor notes), scores every household
each time something happens, and hands the advisor or the Senior Investor Protection team a cited case file before the money
leaves.

## How it works

```
account changes ─┐   Engine A  money movement vs the household's own 12-month baseline (robust z, new payees,
money movement  ─┼─▶ Engine B  account-change sequences (contact change → new bank → withdrawal; new POA → payee match)
advisor notes   ─┘   Engine C  notes reader: Claude extracts FinCEN red flags with exact quotes; injections reported, never followed
                          │
                          ▼
             shallow monotone gradient-boosted fusion, calibrated (isotonic) → score + plain-English reasons with record IDs
                          │
                          ▼
       weekly reviewer budget → advisor queue / pre-release check / specialist queue → case agent (Claude + tools) drafts
       call script, trusted-contact note, escalation memo, APS referral, Rule 2165/2166 deadlines → a person decides
```

* **Scored before money moves.** Every withdrawal request is scored before release, and so is every account change and note.
  Features at a moment use only records before it; a test deletes the future and checks no feature changes.
* **Every claim is cited.** Notes-reader quotes must be exact substrings of the note. Case-file claims must cite a record ID
  that exists for that household. Code rejects anything else; the model is never trusted to police itself.
* **Guardrails in code.** Age is never a model input (fairness is reported by age band). No diagnoses. No draft to a trusted
  contact who may be involved. Nothing is sent or held automatically.
* **Hard rule.** Money moving repeatedly to the trusted contact or a new power of attorney always escalates.

## Run it

Python 3.11+.

```bash
pip install -r requirements.txt
cp .env.example .env            # optional: ANTHROPIC_API_KEY for the Claude notes reader and case agent
make all                        # world → notes → eval → seeds → export → agent → readme
python -m http.server -d web    # open http://localhost:8000
```

On Windows without GNU make, use `mingw32-make all`, or run the steps in the `Makefile` directly. Individual steps:

| Step | Command | Time on a laptop |
|---|---|---|
| Synthetic world (20,000 households, 24 months) | `python -m sentinel.generate` | ~1.5 min |
| Claude notes reader (Batches API, cached) | `python -m sentinel.llm.notes_reader` | depends on batch queue |
| Train, calibrate, evaluate (CIs, leave-one-typology-out, robustness) | `python -m sentinel.eval.run_eval` | ~10 min |
| Repeat on 4 more independent worlds | `python -m sentinel.eval.seeds` | ~25 min |
| Dashboard data | `python -m sentinel.export` | ~2 min |
| Claude case agent for queued households | `python -m sentinel.llm.case_agent` | ~1 min per household |
| Tests | `python -m pytest` | ~1 min |

**Without an API key** everything still runs: the notes engine falls back to a keyword + TF-IDF reader and the case files
to templates, and the dashboard and README say so. Claude outputs are cached by note hash in `sentinel/llm/cache/` and
committed, so the demo works offline once they have been generated.

Models are set by environment variables: `SENTINEL_NOTES_MODEL` (default `claude-haiku-5-5`) and
`SENTINEL_AGENT_MODEL` (default `claude-opus-5-5`).

## The synthetic world

`config/world.yaml` holds every rate and the seed; the same seed reproduces byte-identical files (tested).

* 20,000 households aged 55–95 across 250 advisors with five writing styles; log-normal assets (median ≈ $350k).
* Normal life: monthly withdrawals, RMDs, 1–3 lumpy withdrawals a year (some to new contractors or family), renovation
  instalments, account changes at realistic yearly rates, 2–8 notes a year (15% of households have none).
* **2% of households exploited**, in six typologies with FinCEN loss medians ($33.5k scams, $23.8k theft) and the 80/20
  stranger/trusted-person split. Every signal appears only with some probability; 15% of contact scams come with a
  coached cover story.
* **~1,000 legitimate look-alikes**: home purchases, gifts to family, care-home deposits, moving states (the same shape as an
  account takeover), remarriage, transfers to another firm, trust funding.
* 1% of notes carry prompt-injection text, in scam and normal households alike.
* Labels live only in `data/world/labels/`; the feature code cannot load them (tested).

## Repository

```
config/world.yaml        every rate in the synthetic world, plus the seed
sentinel/generate/       households, typologies, look-alikes, notes and writing styles
sentinel/features/       engine A (money), engine B (sequences), notes features, scoring points
sentinel/llm/            notes_reader (Claude), keyword_reader (baseline), case_agent (Claude + tools), cache/
sentinel/models/         fusion + calibration, reason codes
sentinel/eval/           splits, baselines, alert policy, metrics + bootstrap, robustness, seeds
sentinel/export/         dashboard JSON and this README's results
web/index.html           the dashboard (single file, vanilla JS); reads web/data/*.json
results/                 metrics.json, seeds.json
tests/                   determinism, leakage, quote validation, deadlines, injections, trusted-contact guardrail
```

## Limitations, honestly

* Synthetic data. Advisor notes are template-generated in five styles; real notes are far more varied. The next step is a
  backtest on LPL's past Senior Investor Protection cases, then a silent run alongside today's rules.
* The weekly alert budget is a parameter LPL would set; precision is low at generous budgets and is also reported at a
  realistic 0.5% base rate.
* Personal details are not yet redacted before notes reach the model; in production this would run inside LPL's environment.
* The 85+ age band currently sits above our 1.25× false-alarm target (see Results). Older clients more often add a POA or
  move money to family, which is legitimate; we report it rather than tune it away on test data.
